# Resell

منصة وساطة لإعادة بيع أراضي «بيت الوطن». الخطة الكاملة في دوك «Resell — خطة البرمجة وطريقة العمل».

## التشغيل على جهازك

محتاج: Node.js 20+، و PostgreSQL 16 + PostGIS (على الجهاز أو `docker compose up -d`).

```bash
bash install.sh      # المكتبات
cp .env.example .env # واملا القيم
npm run db:setup     # الجداول + البيانات التجريبية
npm run dev          # http://localhost:3000
```

على ويندوز: خلّي فولدر المشروع في مسار قصير (زي `D:\resell`)، لأن المسارات الأطول من 260 حرف بتبوّظ محرك Prisma.
مستخدم قاعدة التطوير محتاج SUPERUSER على جهازك بس، عشان Prisma يفعّل PostGIS في القاعدة المؤقتة.

| الأمر | بيعمل إيه |
| --- | --- |
| `npm run db:migrate` | بعد أي تعديل في `prisma/schema.prisma` |
| `npm run db:seed` | البيانات التجريبية (بيتخطى لو موجودة) |
| `npm run db:clean -- --yes` | **بيمسح كل البيانات** — بعد ما التجربة تخلص |
| `npm run db:reset-demo` | يمسح ويحط البيانات التجريبية من جديد |
| `npm run db:studio` | تشوف الجداول من المتصفح |
| `npm test` | اختبارات مراحل الصفقة والصلاحيات |

ملحوظة على الـ migrations: Prisma بيحاول يمسح فهرس `Plot_boundary_gist` في كل migration جديدة (مش شايفه في الـ schema). امسح السطر ده من ملف الـ SQL قبل التطبيق.

## البيانات التجريبية

10 نماذج على الأقل في كل حالة، وكل حاجة بمرفقاتها (PDF وصور):
130 عرض في كل الحالات، 90 صفقة في المراحل السبعة (شغالة، متوقفة، ملغية، مكتملة، واتباعت لمشتري تاني)، 240 عقد، 930 مستند،
40 عميل (توثيق مقبول/مستني/مرفوض)، 50 طلب خدمة، 40 طلب شراء، 100 سعر صرف، ومؤشر أسعار 24 شهر لـ 5 مدن.

في الوضع التجريبي (من غير `WHATSAPP_TOKEN`): رمز الدخول بيظهر على الشاشة، وفيه «دخول سريع» بحساب لكل دور.

## قواعد مبرمجة (مش في الشاشة بس)

- مراحل الصفقة state machine بشروط (`src/lib/deal-machine.ts` + اختباراتها).
- المشتري ما يشوفش كود القطعة ولا البائع قبل توقيع اتفاق العمولة، ولا الملفات قبل العقد المبدئي — بيتفحص في الخادم (`src/lib/access.ts`).
- كل فتح مستند وكل فعل حساس بيتسجل في سجل التدقيق، والسجل ما يتعدلش وما يتمسحش (trigger في قاعدة البيانات).
- المستندات ما تتمسحش؛ التعديل بإصدار جديد.
- نسب العمولة وسعر الصرف بيتثبتوا في الصفقة وقت اتفاق السعر.

## التحسينات (الخطوة 4)

كل ميزة محتاجة خدمة برّه بتفضل مقفولة لحد ما إعداداتها تتحط، والسلوك القديم شغال زي ما هو.

| الميزة | فين | بتتفعّل إزاي |
| --- | --- | --- |
| خزنة S3 للملفات | `src/lib/storage.ts` | `S3_*` في الإعدادات |
| تحقق ثنائي (Authenticator) | `/account/security` | متاح لأي حد دلوقتي؛ إجباري للفريق مع `REQUIRE_STAFF_2FA=1` |
| سياسة الخصوصية والشروط | `/privacy` و `/terms` | مسودة — لازم مراجعة المحامي |
| موافقة صريحة + حذف الحساب بالطلب | التسجيل و `/account/security` | شغالة |
| الإشعارات | الجرس في الهيدر و `/notifications` | جوه المنصة شغالة؛ واتساب/إيميل مع ربط المزوّد |
| نسخة جديدة لمستند مرفوض | حسابي ← قطعي | شغالة |
| مطابقة طلبات الشراء | لما الوسيط ينشر عرض | شغالة |
| تنبيهات يومية + سعر صرف آلي | `/api/cron/daily` الساعة 8 الصبح | `CRON_SECRET` على Vercel |
| خريطة القطعة | صفحة القطعة | شغالة (مكان تقريبي قبل اتفاق العمولة) |
| تقرير معاينة PDF | صفحة القطعة ← تقرير المعاينة | شغال (طباعة/حفظ PDF من المتصفح) |
| حاسبة التكلفة | صفحة القطعة | شغالة؛ رسوم التنازل من الإعدادات |
| مراقبة الأخطاء | `src/instrumentation*.ts` | `SENTRY_DSN` |
| اختبارات | `src/lib/*.test.ts` | `npm test` (25 اختبار) |

## النشر على Vercel + Neon

1. `npx vercel login` ثم `npx vercel link`.
2. من لوحة Vercel: Storage ← Create ← Neon، واربطها بالمشروع (بتحط `DATABASE_URL` و `DATABASE_URL_UNPOOLED`).
3. Settings ← Environment Variables: أضف `SESSION_SECRET` (نص عشوائي طويل).
4. `npx vercel --prod` — البناء بيعمل الـ migrations والبيانات التجريبية لوحده (`vercel-build`).
